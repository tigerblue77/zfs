## Why

The leak, as read from the code (not yet confirmed by a run: this task is that run). On Linux 5.10 and older, `__blkdev_get()` (`fs/block_dev.c`, unchanged in 5.10.262) takes a reference on the gendisk and on its driver's module (zfs) at every open, and keeps them only for the first opener: `if (!first_open) put_disk_and_module(disk);`. `first_open` is set to false once, before the `restart:` label, and to true on a pass that finds `bd_openers` at 0. When `fops->open()` returns `-ERESTARTSYS` on a first open, `__blkdev_get()` drops its references and the whole disk's `bd_mutex` and starts again. If another task has opened the device in between, the second pass takes the "already open" branch, the open succeeds (the zvol is open, so `zvol_open()` needs no namespace lock), and since `first_open` is still true from the first pass, the second pass's references are never dropped: one gendisk reference and one zfs module reference per occurrence. `zvol_open()` returns `-ERESTARTSYS` on kernels before 5.13 (configure: `whether blkdev_get_by_path() handles ERESTARTSYS... yes`) whenever a first open cannot take `spa_namespace_lock` at once. `race.sh`'s `zfs set` commands take that lock several times a second, and a second opener is always near: eight openers, each of which may keep the device open between its `open` and its `close` while its 2 % CPU quota is spent. The fix `e256741ff14` does not touch `zvol_open()`, and master has the same code: the leak is not the fix's; on master the GPF of M-41 came first (ZV510C's m1, 164 s in). Linux 5.11 reworked `__blkdev_get()`: there every open holds its own references.

The second commit of `fix2` and `zt2`, "Linux: retry a contended zvol_open() before restarting it" (the patch of step 1): `zvol_open()` waits for the lock for up to `zvol_open_timeout_ms` (1000 ms) on every kernel, as it already did on 5.13 and newer, and only then returns `-ERESTARTSYS`, which 5.12 and older still answer with the restart. `zvol_open_timeout_ms` becomes a module parameter on 5.10 too (on 5.10 it did not exist before). Under `race.sh` the lock is never held for a whole second, so `zvol_open()` should not return `-ERESTARTSYS` at all, and the use count should stay at 0.

Master is not run: ZV510C reproduced its GPF in this same guest (m1, 164 s), and a master run cannot show the leak reliably: it panicked 164 s in, while the fix leaked about once every seven minutes (3 in 21). The reference for the leak is the unchanged fix `e256741ff14` (B3), whose leak ZV510C saw.

The probe. A kretprobe trace event on `zfs:zvol_open` (`r64:`, up to 64 calls tracked at once) records the return value, with a filter that keeps only -512 (`-ERESTARTSYS`). The guest's kernel has `CONFIG_KPROBE_EVENTS=y` and no hist triggers, hence the filter and a line count. `probe.sh on <tag>` sets it up with an 8 MiB trace buffer per CPU; `probe.sh off <tag>` prints `<tag> hits=<all zvol_open() returns> restartsys=<returns of -512> overrun=<events lost>` (appended to the guest's `/var/log/zv510b/probe.txt`) and up to three of the trace lines, then removes the probe. `restartsys` is exact when `overrun=0`, a lower bound otherwise. The probe is set after the pre-run checks and removed before the use count is read (registering it takes a module reference only for the time of the registration). If `probe.sh on` fails, quote its output, run without the probe in this boot (skip `probe.sh off`), and say so: the use count and the unload remain the verdict.

```sh
# TASK-1121-ZV510B open/remove race amplifier, run as root in the guest:
# race.sh <module tree: master|fix> <tag> <seconds>
# The commands are master's (the user-space code of both trees is the same).
```

```python
# TASK-1120-ZVO opener: open and close <dev> in a loop until <end> (epoch s)
import errno
import os
import sys
import time

dev = sys.argv[1]
end = float(sys.argv[2])
n = {"ok": 0, "enxio": 0, "enoent": 0, "other": 0}
while time.time() < end:
    try:
        os.close(os.open(dev, os.O_RDONLY))
        n["ok"] += 1
    except OSError as e:
        if e.errno == errno.ENXIO:
            n["enxio"] += 1
        elif e.errno == errno.ENOENT:
            n["enoent"] += 1
        else:
            n["other"] += 1
print(" ".join("%s=%d" % kv for kv in n.items()))
```
