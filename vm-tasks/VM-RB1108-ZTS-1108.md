# VM task: the ZTS tests of the drain series and of its three PRs, on rb1108 (8/11)

These instructions are for one 16-vCPU test VM: VM 105, VM 106 or VM 107,
whichever is free, as long as it runs Debian 13 with a 6.12 kernel (STEP 0
checks). Reply with `/var/log/rb1108-zts/REPORT.txt` (STEP 6). Nothing is
posted, pushed or installed, apart from two udev links that STEP 5 removes.

**A functional test, not a performance one.** It checks what the tests
report, not how fast anything runs: it may run while one other VM runs a
functional job (ztest, zloop, ZTS, a replay), but not while two do, and never
while one of them runs a performance test. The three VMs share one
hypervisor: this task's debug build and pool I/O would skew a measurement
there, and some ZTS tests have time limits (`removal_with_zil` fails when a
removal takes more than 60 s), which a busier host could break for no reason
in the code. Nothing else runs on this VM meanwhile.

**Background.** The fork branch `rewrite-series-v3-rb1108`, head
`ff753bcee69b53cfeb6b449d732ac1e49cc3321d` ("Report the rewrite of a volume
in zpool rewrite -v"), is upstream master `2796b5da69` ("zfs_znode (Linux):
Optimize hold insertion") with three open PRs merged (merge `59b712ebb2`) and
15 commits on top:

- #19373: `zpool remove` turns an empty top-level vdev of any type, in any
  pool, into a hole, with no indirect vdev, and erases its labels.
- #19367: `zfs rewrite` rewrites volumes; the marking of the blocks moves
  into the DMU.
- #19388: the `allocation_classes` feature goes back to `enabled` when no
  class vdev is left, and stays `active` while a vdev is special on disk.
- The series: `zfs rewrite -A` (only the blocks with a copy on a vdev whose
  `allocating` is `off`), the rewrite of spill blocks, dnode blocks,
  directories, accounting objects, whole file systems and whole volumes,
  `zpool rewrite` with the pool's own metadata, the drain helpers, the
  `allocation_classes` refcount when an empty vdev goes, a ztest of the drain
  under load, and `ff753bcee6`: `zpool rewrite -v` reported every volume as
  done with 0 objects and 0B marked, and now reports what it marked;
  `zpool_rewrite_drain` now requires `vol: done, 2 objects,` for its volume.

VM-DRAIN-RAIDZ-1108 ran the drain end to end by hand, on the previous head
`32333813ac`, and its cases 1 to 3 passed. None of the ZTS tests that the
series and the three PRs add or change has run yet with a kernel module.
This task runs them, with five unchanged neighbours as controls, and nothing
else of the ZTS.

**What runs.** One debug build of the head, loaded with `insmod`, and two
udev links so that volumes get their `/dev/zvol` names, which most of these
tests use. Then `zts.sh` runs the 21 tests below one at a time, each with its
own `scripts/zfs-tests.sh -v -d $F -t <test>`. That is the zfs-tests.sh
default for devices: three sparse 4 GiB files in F with a loop device on each
(`DISKS` is never set), and the tests that build their own pools do so on
files in F. Each run makes its devices, runs the setup script of the test's
directory if there is one, the test, then the cleanup script, and removes its
devices and files. After each test `zts.sh` records the result and the
durations, keeps the logs, and checks the kernel log and what is left.

**Duration**: STEP 0 2 min; STEPS 1 and 2, the build and the load, about 15

which stops the run); STEPS 5 and 6 about 5 min. About 1 h 10 min in all.

## Rules

- Disposable VM only, with nothing else running on it. This task loads and
  unloads the ZFS module stack it builds, and ZTS creates and destroys pools
  named `testpool...`, loop devices over sparse files in F, and volumes.
  Never set `DISKS` (`zts.sh` unsets it): no block device of the VM is used.
  Never pass `-x` to zfs-tests.sh (it destroys every pool whose name
  contains `testpool`), nor `-k`, `-R` or `-I`.
- One debug build (`--enable-debug`), under `nice -n 10 ionice -c3` with
  `make -j8`.
- Post nothing, push nothing. Install nothing (no `make install`, no
  `zfs-helpers.sh`, no package), except the two udev links of STEP 2, which
  STEP 5 removes. Never reboot.
- Work only under `/var/tmp/rb1108-zts` (W) and `/var/log/rb1108-zts` (L).
  ZTS itself also writes, as on any test machine: its loop devices, the
  `/dev/zvol` links, the mount points of its pools under `/` while they
  exist, and `/var/tmp/test_results/<time>`, which `zts.sh` moves into L
  after each test. Never run `zpool`, `zfs` or `zdb` while this task's
  modules are not loaded.
- Run each block as your usual user, not root, in bash, with passwordless
  sudo: the blocks call `sudo -n` themselves where root is needed, and
  zfs-tests.sh refuses to run as root and calls sudo itself.
- If a check does not print what its comment says, stop and report; do not
  rebuild, repair or retry. In STEP 3 a test's FAIL or SKIP is a result, not
  a stop: `zts.sh` records it, keeps the test's log directory and the kernel
  log since the test started, and goes on to the next test. Never run a test
  a second time. A `STOP` line of `zts.sh`, a panic, oops, `VERIFY`,
  `ASSERT`, `BUG:`, `WARNING` or hung-task message: stop, run STEP 4, write
  the REPORT (STEP 6) and reply, and leave everything as it is: pools, loop
  devices, files, the modules loaded, W in place, for diagnosis. Run STEP 5
  (the cleanup) only when the run ended without a STOP, or when the reply
  asks for it.
- If `zts.sh` prints nothing for 20 minutes, treat it as a STOP: no test may
  run longer than 600 s. STEP 4, run from a second shell, records the kernel
  log and the stuck processes. Do not kill a process in state `D`.
- If your shell tool cannot wait for a long command in the foreground, start
  that one command with the tool's own background mode and wait until it
  exits; do not use `&` or `nohup`, and run nothing else meanwhile.

## STEP 2: the scripts, the modules and the udev links (2 min)

`tests.txt` is the list of the table above, in its order. `zts.sh` runs each
test on its own with `zfs-tests.sh -v -d $F -t <test>` and writes one line
per test to `$L/results.tsv`: the result, the test's own duration (`time`,
as test-runner prints it), the results of the setup and cleanup scripts, the
whole run in seconds (`wall_s`), the exit status of zfs-tests.sh, and
whether the module parameters are as before the first test. Then the
modules are loaded, the two udev links made, and a probe checks that a
volume gets its `/dev/zvol` link.

```sh

cat > $L/tests.txt <<'EOF2'

# takes them.  Controls: unchanged tests next to what the series changes.

cat > $L/zts.sh <<'EOF2'
#!/bin/bash
# zts.sh: VM-RB1108-ZTS-1108, run as the test user, never as root.  Runs each
# test of tests.txt on its own with zfs-tests.sh -t and writes one line per
# test to results.tsv.  A FAIL or SKIP is recorded with the test's logs and
# the run goes on; a KILLED test, a missing result, a kernel message, a pool,
# loop device, vdev file or mount left behind, or the module of the build no
# longer loaded stops everything and leaves it in place for diagnosis.
. /var/log/rb1108-zts/env.sh
set -u
[ "$(id -u)" != 0 ] || { echo "zts.sh: run as the test user, not root"; exit 2; }
R=$L/zts T=$L/results.tsv
[ -e "$T" ] && { echo "zts.sh: $T exists: the tests run once"; exit 2; }
# Each of these would make zfs-tests.sh use other devices, pools or files.
unset DISKS KEEP FILES LOOPBACKS RUNFILES FILEDIR STF_PATH STF_SUITE STF_TOOLS
mkdir -p "$R" "$F" && chmod 1777 "$F" || exit 1

log() { echo "[$(date -u +%T)] $*" | tee -a "$R/log.txt"; }
stop() {
	log "STOP: $*"
	echo "$*" >> "$L/stops.txt"
	exit 1
}
kmsg() { echo "rb1108-zts: $*" | sudo -n tee /dev/kmsg > /dev/null; }
tunables() {
	sudo -n grep -H . /sys/module/zfs/parameters/* 2> /dev/null |
	    sed 's|^/sys/module/zfs/parameters/||'
}
# res <test path>: "RESULT MM:SS" from its line in the output of zfs-tests.sh
res() {
	grep -F "/$1 (run as" "$O/zfs-tests.txt" | tail -1 |
	    sed -nE 's/.*\[([0-9:]+)\] \[([A-Z]+)\].*/\2 \1/p'
}

SV=$(modinfo -F srcversion "$Z/module/zfs.ko")
# zfs-tests.sh sets it at each run: set it first, so that it is no change.
echo 1 | sudo -n tee /sys/module/zfs/parameters/zfs_dbgmsg_enable > /dev/null
tunables > "$R/tunables-0.txt"
printf 'id\tresult\ttime\tsetup\tcleanup\twall_s\texit\ttunables\n' > "$T"
log "start: $(grep -c '^tests/' "$L/tests.txt") tests"
n=0
while read -r t <&3; do

	n=$((n + 1))

	id=$(printf '%02d-%s' "$n" "${base%.ksh}")

	mkdir -p "$O" || stop "$id: mkdir $O"
	[ -x "$Z/tests/zfs-tests/$t" ] || stop "$id: no executable $t"
	log "$id: start"
	kmsg "$id start"
	t0=$(date +%s)
	"$Z/scripts/zfs-tests.sh" -v -d "$F" -t "$t" > "$O/zfs-tests.txt" 2>&1 < /dev/null
	rc=$?
	wall=$(($(date +%s) - t0))
	kmsg "$id end"
	sudo -n dmesg | sed -n "/rb1108-zts: $id start/,\$p" > "$O/dmesg.txt"
	read -r r tm <<< "$(res "$t")"
	s=$(res "${t%/*}/setup")
	c=$(res "${t%/*}/cleanup")
	tunables > "$O/tunables.txt"
	if diff "$R/tunables-0.txt" "$O/tunables.txt" > "$O/tunables.diff"; then
		tu=same
		rm -f "$O/tunables.diff"
	else
		tu=changed
	fi
	printf '%s\t%s\t%s\t%s\t%s\t%s\t%s\t%s\n' "$id" "${r:-NONE}" "${tm:--}" \
	    "${s:--}" "${c:--}" "$wall" "$rc" "$tu" | tr ' ' _ >> "$T"
	log "$id: ${r:-NONE} ${tm:--} (setup ${s:--}, cleanup ${c:--}," \
	    "$wall s, exit $rc, tunables $tu)"
	[ "$n" = 1 ] && log "missing utils:" \
	    "$(sed -n 's/^Missing util(s): *//p' "$O/zfs-tests.txt")"
	ld=$(awk '/^Log directory/ { print $3 }' "$O/zfs-tests.txt")
	if [ -n "$ld" ] && [ -d "$ld" ]; then
		mv "$ld" "$O/log" || log "$id: could not move $ld"
	fi
	if [ "${r:-NONE}" != PASS ]; then
		# merged exists when the test wrote to both stdout and stderr
		m=$(find "$O/log" \( -path "*/$base/merged" -o \
		    -path "*/$base/stdout" \) 2> /dev/null | sort | head -1)
		[ -n "$m" ] && sed '/Performing test-fail callback/q' "$m" |
		    tail -80 > "$O/excerpt.txt"
		tail -100 "$O/dmesg.txt" > "$O/dmesg-tail.txt"
	fi
	ls -A "$F" > "$O/leftover.txt"
	[ -s "$O/leftover.txt" ] || rm -f "$O/leftover.txt"

	grep -q "rb1108-zts: $id start" "$O/dmesg.txt" ||
	    stop "$id: its start marker is not in the kernel log"
	k=$(grep -E 'VERIFY|ASSERT|PANIC|BUG:|Oops|Call Trace|blocked for more|WARNING:|general protection' "$O/dmesg.txt")
	[ -z "$k" ] || stop "$id: kernel message: $(printf '%s\n' "$k" | head -1)"
	case ${r:-NONE} in
	PASS | FAIL | SKIP) ;;
	KILLED) stop "$id: KILLED at the ZTS timeout of 600 s" ;;
	*) stop "$id: no result from zfs-tests.sh (exit $rc):" \
	    "$(tail -3 "$O/zfs-tests.txt" | tr '\n' ' ')" ;;
	esac
	[ "$(cat /sys/module/zfs/srcversion 2> /dev/null)" = "$SV" ] ||
	    stop "$id: the zfs module of the build is no longer loaded"
	left=$(sudo -n "$Z/zpool" list -H -o name 2>&1)

	left=$(sudo -n losetup -a | grep -F "$F/")
	[ -z "$left" ] || stop "$id: loop device left: $(printf '%s' "$left" | tr '\n' ' ')"
	compgen -G "$F/file-vdev*" > /dev/null && stop "$id: file-vdev files left in $F"
	grep -q ' zfs ' /proc/mounts && stop "$id: a zfs file system is still mounted"
	[ "${r:-NONE}" = PASS ] || log "$id: ${r:-NONE}: logs kept in $O"
done 3< "$L/tests.txt"
log "done: $n tests:$(tail -n +2 "$T" | cut -f2 | sort | uniq -c | tr -s ' \n' ' ')"
exit 0
EOF2
```
