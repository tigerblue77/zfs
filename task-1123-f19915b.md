## Why

- **The bug:** on a full pool, or on a file system at its `refquota`, `fsync(2)`, `fdatasync(2)` and `msync(MS_SYNC)` on a file with dirty mmap'd pages return 28 (ENOSPC) or 122 (EDQUOT) with errno 0, instead of -1 with errno set. `zpl_putpage()` passes on `zfs_putpage()`'s positive errno. The fix negates it and asserts `ret <= 0`; it is unchanged since the last task.
- **Last task (TASK-1123-F19915, VM 106, Linux 6.12.118, debug builds):** the fix works. With it, the three calls returned -1/EDQUOT at the refquota and -1/ENOSPC on the full pool, 0 otherwise; on master they returned 122 with errno 0 and the `writeback_iter` WARNING fired once; the test alone failed 2/2 at the EDQUOT check; groups `mmap` and `failmode` otherwise all PASS. **But the test had two defects, fixed here:**
  1. Its last step never ran. On the full pool, the second fill pass (`dd ... of=/var/tmp/testdir1/fill2 bs=128k`) cannot even create `fill2`, so `log_must rm $TESTDIR1/fill $TESTDIR1/fill2` failed ("No such file or directory") on every run of the fix. Now it is `rm -f`. And since removing a file that large frees its blocks in the background, after `rm` returns, the test now syncs the pool and waits, at most 60 seconds, until the file system has room to write the 8 MiB file back twice over (`available` at least twice `referenced`), before the final check that each call returns 0. On a timeout it fails with `no room after removing the fill:` and the space of each dataset.
  2. `zfs-tests.sh -t mmap_sync_error` could not select the test from a build tree: it resolves a bare name with `find "$STF_SUITE" -name "$SINGLETEST*" -print -quit`, which found the helper `tests/zfs-tests/cmd/mmap_sync_error.c` first. The helper is now `mmap_sync_errno` (same code, renamed, its usage line updated), so the find matches the test alone.
- **The test** `mmap_sync_error` (mmap group, Linux runfile), with its helper `mmap_sync_errno <file> 0|ENOSPC|EDQUOT`: a pool `testpool1` on a 256 MiB file vdev `/var/tmp/mmap_sync_error.vdev`, mounted at `/var/tmp/testdir1`, an 8 MiB file `fs/file`. The helper stores into every page of a shared mapping of the file, then calls `fsync`, `fdatasync` and `msync(MS_SYNC)` in turn (storing again before each), prints `<call>: returned <n>, errno <e> (<text>)` for each, and exits 1 unless each returned what was expected. Order: refquota set to `referenced` → expect EDQUOT; refquota removed → expect 0; pool filled with two `dd` passes until ENOSPC → expect ENOSPC; fill files removed, then the wait for space → expect 0.
