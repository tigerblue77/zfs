## Why

TASK-1120-M21, step 4: on the 2.4 after kit (`baeb0f56a87`, debug build, kernel 6.12), the first run of `raidz_expand_scratch_uberblock` panicked in its second case, `VERIFY3U(rc->rc_offset + rc->rc_size, <, cvd->vdev_psize - VDEV_LABEL_END_SIZE) failed (18446744073705882112 < 267911168)`, `PANIC at vdev_raidz.c:2455:vdev_raidz_io_start_write()` in `z_wr_iss`, right after `reflow: error 5 writing uberblock (SCRATCH_INVALID_SYNCED)`; the release build of the same kit passed 3 of 3.

The cause, as main reads it: when the second scratch uberblock fails, the port leaves the expansion paused with `spa_ubsync` in `RRSS_SCRATCH_VALID` (the scratch area stays in use, by design). While it is paused, `vdev_raidz_map_alloc_expanded()` maps every write to the first 17.5 MiB of the vdev into the scratch area by subtracting `VDEV_BOOT_SIZE` (3.5 MiB) from the column offset, which wraps below zero; `zio_vdev_child_io()` adds the 4 MiB of front labels back, so the write lands in the boot area as intended. The bounds `ASSERT3U()`s of `vdev_raidz_io_start_write()` compare the wrapped value directly. They exist only in debug builds, so a release build writes to the scratch area and the retry copies it to its place ("O U0"). 18446744073705882112 is 2^64 - 3670016 + 512: a 512-byte column at offset 0 of the new layout, mapped to the scratch area. Upstream master fixed those assertions in `5e672734420` ("raidz: fix write ASSERTs for scratch area columns", #19590), which zfs-2.4.5-staging does not have; master's own version of the fix (`raidz-scratch-ub-no-panic-v4`) already runs with it.

Main reproduced this in userspace (libzpool, which always has the debug assertions): with the expansion paused after a failed SCRATCH_INVALID_SYNCED uberblock, one write to a freed block at offset 73728 of the vdev aborts the 2.4 after kit at the same `vdev_raidz.c:2455` with the same right-hand side, 267911168. With `5e672734420`'s change added, and on master's v4, the same write goes to the scratch area, the expansion completes, and the data read back after an export and an import are intact, with a clean scrub. Whether a write lands in that window in this test depends on where the sync thread allocates in the txg of the failure: the userspace runs of the plain scenario never did (11 of 11), the kernel run of TASK-1120-M21 did at once.

This task checks it on the kernel modules, with the test of TASK-1120-M21, each build debug:

1. `fx`: the after kit with `5e672734420`'s change, 5 runs. Expected PASS 5 of 5.
2. `mv`: master's version, `raidz-scratch-ub-no-panic-v4`, 5 runs. Expected PASS 5 of 5.
3. `ad`: the after kit of TASK-1120-M21 again, rebuilt in place, at most 3 runs, stopping at the first panic. Expected: the assertion of TASK-1120-M21 again, in its second case.

Two kprobe counters on `zio_vdev_child_io()` (`kp.sh`, tracefs, no code change) show in `fx` and `mv` whether the window was hit: `area` counts the child i/o below offset 0 (the scratch phase's own reads and writes of the scratch area, 20 per run, plus the following), `scratch` those smaller than the scratch area, which only blocks mapped there by `vdev_raidz_map_alloc_expanded()` can be. A `scratch` count above 0 in a passing run is the case that panicked TASK-1120-M21.

`kp.sh on|off` runs as root. `on` adds the two kprobe events `m21b/scratch` and `m21b/area` on `zio_vdev_child_io()` with their filters, enables them, empties the trace buffer and prints `KPROBE-ON` with the filters and the two event definitions; on any error it removes what it added and exits 1. `off` disables and removes them and prints `KPROBE-OFF 0`.

```sh
#!/bin/sh
# TASK-1120-M21B counters of child i/o below offset 0, as root: kp.sh on|off
# area: every such i/o; scratch: those smaller than the scratch area, which
# are blocks that vdev_raidz_map_alloc_expanded() mapped there.
E=/sys/kernel/tracing
off() {
    echo 0 > $E/events/m21b/enable 2>/dev/null
    echo '-:m21b/scratch' >> $E/kprobe_events 2>/dev/null
    echo '-:m21b/area' >> $E/kprobe_events 2>/dev/null
    echo "KPROBE-OFF $(grep -c m21b $E/kprobe_events)"
}
case $1 in
on)
    for p in scratch area; do
        echo "p:m21b/$p zio_vdev_child_io off=\$arg4:u64 size=\$arg6:u64 type=\$arg7:s32" \
            >> $E/kprobe_events || { off; exit 1; }
    done
    echo 'off >= 9223372036854775808 && size < 3670016' \
        > $E/events/m21b/scratch/filter || { off; exit 1; }
    echo 'off >= 9223372036854775808' > $E/events/m21b/area/filter ||
        { off; exit 1; }
    echo 1 > $E/events/m21b/enable || { off; exit 1; }
    echo > $E/trace
    echo "KPROBE-ON scratch=[$(cat $E/events/m21b/scratch/filter)]" \
        "area=[$(cat $E/events/m21b/area/filter)]"
    grep m21b $E/kprobe_events
    ;;
off)
    off
    ;;
*)
    exit 2
    ;;
esac
```

`pf.sh <tag> <tree> <runs>` runs as root, detached. For each run, after the pre-run checks, it starts the test as `zts` under `timeout 1500` and watches this boot's kernel log for a new `VERIFY`, `ASSERT` or `PANIC` line until the runner ends, for at most 5 minutes. On such a line it writes `PANIC-SEEN <tag>-<n> +<s>s <that line>` to `$L/pf-<tag>.txt`, saves the ring (`$L/dmesg-<tag>-<n>-panic.txt`) and the debug log (`$L/dbgmsg-<tag>-<n>.txt`, its reflow lines in `$L/dbg-<tag>-<n>.txt`), waits 30 seconds, runs `cap.sh` and ends with `PF-END <tag> PANIC run=<n> ... dstate=<n>`. A runner still going after 5 minutes without such a line: `cap.sh`, then `PF-END <tag> HANG ...`. A run that ends without one gets the line `<tag>-<n> NOPANIC result=[<mm:ss>] [<result>] secs=<s> reflow=<lines>` and the next run starts; after the last, `PF-END <tag> NOPANIC runs=<runs>`. It never runs `zpool` or `zfs` after a run has started.

```sh
#!/bin/sh
# TASK-1120-M21B runs that may panic, as root: pf.sh <tag> <tree> <runs>
# Stops at the first VERIFY, ASSERT or PANIC of this boot's kernel log.
PATH=$PATH:/usr/sbin:/sbin
D=/var/tmp/task-1120-m21b
L=/var/log/task-1120-m21b
T=raidz_expand_scratch_uberblock
tag=$1
Z=$D/$2
runs=$3
out=$L/pf-$tag.txt
cd $Z || exit 1
sv=$(modinfo -F srcversion $Z/module/zfs.ko)
echo "START $tag $(date -u +%FT%TZ) tree=$2 srcversion=$sv" >> $out
n=1
while [ $n -le $runs ]; do
    loaded=$(cat /sys/module/zfs/srcversion 2>&1)
    pools=$(timeout 30 $Z/zpool list -H -o name 2>&1)
    inj=$(timeout 30 $Z/zinject 2>&1 | head -n 1)
    left=$(ls -d /var/tmp/file-vdev* /var/tmp/dev-* 2>/dev/null)
    if [ "$loaded" != "$sv" ] || [ -n "$pools" ] ||
        [ "$inj" != "No handlers registered." ] || [ -n "$left" ] ||
        [ -s /etc/zfs/zpool.cache ]; then
        echo "STOP before $tag-$n: loaded=[$loaded] pools=[$pools]" \
            "zinject=[$inj] left=[$left]" \
            "cache=[$(ls -l /etc/zfs/zpool.cache 2>&1)]" >> $out
        exit 1
    fi
    sleep 2
    j0=$(journalctl -k -b --no-pager | grep -a -c -E 'VERIFY|ASSERT|PANIC')
    t0=$(date +%s)
    setsid nohup sudo -n -u zts timeout 1500 ./scripts/zfs-tests.sh -vKO \
        -t $T > $L/zts-$tag-$n.log 2>&1 < /dev/null &
    # Until the first new VERIFY/ASSERT/PANIC line, the runner's end, or
    # 5 minutes.
    hit=
    while [ $(($(date +%s) - t0)) -lt 300 ]; do
        sleep 2
        hit=$(journalctl -k -b --no-pager | grep -a -E 'VERIFY|ASSERT|PANIC' |
            tail -n +$((j0 + 1)) | head -n 1)
        [ -n "$hit" ] && break
        pgrep -f "zfs-tests.sh -vKO -t $T" > /dev/null || break
    done
    if [ -n "$hit" ]; then
        echo "PANIC-SEEN $tag-$n +$(($(date +%s) - t0))s $hit" >> $out
        dmesg > $L/dmesg-$tag-$n-panic.txt 2>&1
        timeout 20 cat /proc/spl/kstat/zfs/dbgmsg > $L/dbgmsg-$tag-$n.txt 2>&1
        grep -a ': reflow' $L/dbgmsg-$tag-$n.txt > $L/dbg-$tag-$n.txt
        # Let the threads that wait on the stuck zio settle.
        sleep 30
        dstate=$(ps -eo stat= | grep -c '^D')
        sh $L/cap.sh $tag $L/zts-$tag-$n.log >> $out 2>&1
        echo "PF-END $tag PANIC run=$n +$(($(date +%s) - t0))s" \
            "dstate=$dstate $(date -u +%FT%TZ)" >> $out
        exit 0
    fi
    if pgrep -f "zfs-tests.sh -vKO -t $T" > /dev/null; then
        dstate=$(ps -eo stat= | grep -c '^D')
        sh $L/cap.sh $tag $L/zts-$tag-$n.log >> $out 2>&1
        echo "PF-END $tag HANG run=$n +$(($(date +%s) - t0))s" \
            "dstate=$dstate $(date -u +%FT%TZ)" >> $out
        exit 0
    fi
    timeout 20 cat /proc/spl/kstat/zfs/dbgmsg |
        awk -v t=$t0 '$1 >= t && /: reflow: /' > $L/dbg-$tag-$n.txt
    res=$(sed 's/\x1b\[[0-9;]*m//g' $L/zts-$tag-$n.log |
        grep -oE "/$T(\.ksh)? .*\[[A-Z]+\]" |
        grep -oE '\[[0-9:]+\] \[[A-Z]+\]$')
    echo "$tag-$n NOPANIC result=$res secs=$(($(date +%s) - t0))" \
        "reflow=$(wc -l < $L/dbg-$tag-$n.txt)" >> $out
    n=$((n + 1))
done
echo "PF-END $tag NOPANIC runs=$runs $(date -u +%FT%TZ)" >> $out
```

`cap.sh <tag> <console log>` runs as root and runs no `zpool` or `zfs` command. It saves the kernel ring (`$L/dmesg-<tag>.txt`), this boot's kernel log from the journal (`$L/journal-<tag>.txt`) and the debug log (`$L/dbgmsg-<tag>.txt`), and writes to `$L/cap-<tag>.txt`: the first `VERIFY`, `ASSERT` or `PANIC` line of this boot with the 40 lines after it (from the journal, or the ring when the journal has none), the hung-task reports, the threads in state D and the zfs threads with their wait channels, the kernel stack of every thread in state D, of `txg_sync` and `raidz_expand`, and of any thread in `spl_panic`, the last 40 lines of the console log, and the debug log's reflow and `command:` lines and last 20 lines. Then `sync -f`.

```sh
#!/bin/sh
# TASK-1120-M21B capture of a stuck module, as root: cap.sh <tag> <console log>
# Runs no zpool or zfs command: they would block.
L=/var/log/task-1120-m21b
tag=$1
log=$2
out=$L/cap-$tag.txt
dmesg > $L/dmesg-$tag.txt 2>&1
journalctl -k -b --no-pager > $L/journal-$tag.txt 2>&1
# The journal keeps what a test's "dmesg -c" removes from the ring.
k=$L/journal-$tag.txt
grep -a -q -E 'VERIFY|ASSERT|PANIC' $k || k=$L/dmesg-$tag.txt
{
    echo "CAPTURE $tag $(date -u +%FT%TZ), up since $(uptime -s)"
    echo "== first VERIFY/ASSERT/PANIC of this boot, and 40 lines after it ($k)"
    grep -a -m 1 -A 40 -E 'VERIFY|ASSERT|PANIC' $k
    echo "== hung-task reports"
    grep -a 'blocked for more than' $k
    echo "== threads in D state, and the zfs threads"
    ps -eLo pid,tid,stat,comm,wchan:32 |
        awk 'NR == 1 || $3 ~ /^D/ || $4 ~ /^(txg_|z_null|z_wr_iss|raidz|zpool|zinject|ksh)/'
    for t in /proc/[0-9]*/task/[0-9]*; do
        st=$(cat $t/stack 2>/dev/null) || continue
        c=$(cat $t/comm 2>/dev/null)
        s=$(sed 's/.*) //' $t/stat 2>/dev/null | cut -d ' ' -f 1)
        case "$s $c $st" in
        D\ *|*\ txg_sync\ *|*\ raidz_expand\ *|*spl_panic*)
            echo "== stack of ${t#/proc/} ($c, state $s)"
            echo "$st"
            ;;
        esac
    done
    echo "== console log, last 40 lines"
    tail -n 40 "$log"
    echo "== debug log: reflow and command lines, then its last 20 lines"
    timeout 20 cat /proc/spl/kstat/zfs/dbgmsg > $L/dbgmsg-$tag.txt 2>&1
    grep -a -E ': reflow|command: ' $L/dbgmsg-$tag.txt | tail -n 40
    tail -n 20 $L/dbgmsg-$tag.txt
} > $out 2>&1
sync -f $out $k $L/dbgmsg-$tag.txt
echo "CAPTURED $tag: $out"
```
