## Why

Fork branch `raidz-expand-fixes-2.4` (head `a32ca83e6d9`, six commits on upstream `zfs-2.4.5-staging` `eb011f2aff3`) backports #19440 and #19550 to 2.4.5. The backport of #19440 (`333e2740467`) turned the two scratch-phase uberblock writes of a RAID-Z expansion from `ASSERT0()` into `VERIFY0()`, so that release builds write them at all (TASK-1117-BP24 saw them written on a release build). The other side of it: when no disk takes one of those two uberblocks, a release build now panics in `txg_sync`. A debug build stops one step earlier, in `zio_done()`, because the label writes are issued without `ZIO_FLAG_CANFAIL`. TASK-1118-SUB3 showed both on master and checked the fix there. The fix, ported to 2.4 as `raidz-scratch-ub-no-panic-2.4` (`b549328cde0`, one commit on `a32ca83e6d9`, cherry-picked from master's `0a4bf7d5243`, with `vdev_uberblock_sync_list()` called without the `spa` argument 2.4 does not have), issues those writes with `ZIO_FLAG_CANFAIL` and, when one fails, pauses the expansion as for any other error there; the expansion retries once the error is cleared. The import path (`vdev_raidz_reflow_copy_scratch()`) keeps its `VERIFY0()`, since 2.4 lacks #19590: not covered here, nor FreeBSD.

The test is `raidz_expand_scratch_uberblock`, byte for byte master's (the file TASK-1118-SUB3 ran). For each of the two uberblocks it creates a raidz1 pool of four 256 MiB files `/var/tmp/dev-1` to `dev-4`, writes 64 MiB, holds the sync thread at a zinject point just before that uberblock (`zinject -w raidz_reflow_scratch_sync:written`, then `:reflowed`), attaches `/var/tmp/dev-5`, injects errors on the uberblock area of every child's labels, and releases the thread. With the fix, the uberblock write fails (debug log `reflow: error 5 writing uberblock (<state>)`), the txg's own uberblock fails as well and the pool suspends; the test removes the injection, `zpool clear` resumes the pool, the expansion retries and completes, and the data survive an export and an import. Without the fix, only the first case runs: a release build fails `VERIFY0(vdev_uberblock_sync_list(...)) failed (5)` and stops `txg_sync` in `spl_panic` (`PANIC at vdev_raidz.c:4680:raidz_reflow_scratch_sync()`); a debug build fails `VERIFY(zio->io_error == 0 || (zio->io_flags & ZIO_FLAG_CANFAIL)) failed` (`PANIC at zio.c:5874:zio_done()`) in a `z_null_int` thread, and `txg_sync` then waits for good in `zio_wait` <- `vdev_uberblock_sync_list` <- `raidz_reflow_scratch_sync` (a hung-task report after 120 seconds). Either way the module is wedged: each fail-before ends with a reboot.

2.4 has no `zinject -w`, so the test runs only on two TEST-ONLY kits, never part of the 2.4 pull request. What you fetch from the fork https://github.com/tigerblue77/zfs:

Run n's console goes to `$L/zts-<tag>-<n>.log`, its new kernel lines to `$L/dmesg-<tag>-<n>.txt`, its `reflow:` lines of the debug log to `$L/dbg-<tag>-<n>.txt`, and `$L/runs-<tag>.txt` gets the line `<tag>-<n> rc=<rc> result=[<mm:ss>] [<result>] secs=<s> notes=<k> SEQ-OK|SEQ-OTHER [<sequence>] suspended=<s> resumed=<r> bad=<b> dmesg=kept|cleared dir=<result dir>`. `fb.sh <tag> <tree>` runs as root, detached. After the pre-run checks it starts the test once, as `zts`, under `timeout 1500`, then watches the kernel ring for up to 5 minutes. On the first `VERIFY`, `ASSERT` or `PANIC` line it writes `PANIC-SEEN <tag> +<s>s <that line>` to `$L/fb-<tag>.txt`, saves the ring (`$L/dmesg-<tag>-panic.txt`) and the debug log's reflow lines (`$L/dbg-<tag>.txt`) at once, waits up to 250 seconds for the first hung-task report, runs `cap.sh`, and ends with `FB-END <tag> PANIC +<s>s dstate=<n> result=[] <time>`. With no such line in 5 minutes it waits for the runner (at most its 1500 s), runs `cap.sh` and ends with `FB-END <tag> NOPANIC ... result=[<mm:ss>] [<result>]`. It never runs `zpool` or `zfs` after the start.

    done

    grep -oE '\[[0-9:]+\] \[[A-Z]+\]$')
echo "FB-END $tag $verdict +$(($(date +%s) - t0))s dstate=$dstate" \
    "result=[$res] $(date -u +%FT%TZ)" >> $out

`cap.sh <tag> <console log>` runs as root and runs no `zpool` or `zfs` command. It saves the kernel ring (`$L/dmesg-<tag>.txt`), this boot's kernel log from the journal (`$L/journal-<tag>.txt`) and the debug log (`$L/dbgmsg-<tag>.txt`), and writes to `$L/cap-<tag>.txt`: the first `VERIFY`, `ASSERT` or `PANIC` line of this boot with the 30 lines after it, the hung-task reports, the threads in state D and the zfs threads with their wait channels, the kernel stack of every thread in state D, of `txg_sync`, `raidz_expand` and `z_null_int`, and of any thread in `spl_panic`, the last 40 lines of the console log, and the debug log's reflow lines and last 20 lines. Then `sync -f`.

```sh
#!/bin/sh
# TASK-1120-M21 capture of a stuck module, as root: cap.sh <tag> <console log>
# Runs no zpool or zfs command: they would block.
L=/var/log/task-1120-m21
tag=$1
log=$2
out=$L/cap-$tag.txt
dmesg > $L/dmesg-$tag.txt 2>&1
journalctl -k -b --no-pager > $L/journal-$tag.txt 2>&1
k=$L/dmesg-$tag.txt
grep -q -E 'VERIFY|ASSERT|PANIC' $k || k=$L/journal-$tag.txt
{
    echo "CAPTURE $tag $(date -u +%FT%TZ), up since $(uptime -s)"
    echo "== first VERIFY/ASSERT/PANIC of this boot, and 30 lines after it ($k)"
    grep -m 1 -A 30 -E 'VERIFY|ASSERT|PANIC' $k
    echo "== hung-task reports"
    grep 'blocked for more than' $k
    echo "== threads in D state, and the zfs threads"
    ps -eLo pid,tid,stat,comm,wchan:32 |
        awk 'NR == 1 || $3 ~ /^D/ || $4 ~ /^(txg_|z_null|raidz|zpool|zinject|ksh)/'
    for t in /proc/[0-9]*/task/[0-9]*; do
        st=$(cat $t/stack 2>/dev/null) || continue
        c=$(cat $t/comm 2>/dev/null)
        s=$(sed 's/.*) //' $t/stat 2>/dev/null | cut -d ' ' -f 1)
        case "$s $c $st" in
        D\ *|*\ txg_sync\ *|*\ raidz_expand\ *|*\ z_null_int\ *|*spl_panic*)
            echo "== stack of ${t#/proc/} ($c, state $s)"
            echo "$st"
            ;;
        esac
    done
    echo "== console log, last 40 lines"
    tail -n 40 "$log"
    echo "== debug log: reflow lines, then its last 20 lines"
    timeout 20 cat /proc/spl/kstat/zfs/dbgmsg > $L/dbgmsg-$tag.txt 2>&1
    grep ': reflow' $L/dbgmsg-$tag.txt | tail -n 30
    tail -n 20 $L/dbgmsg-$tag.txt
} > $out 2>&1
sync -f $out $k $L/dbgmsg-$tag.txt
echo "CAPTURED $tag: $out"
```
