== protocol as run
8 cases (retained 0, 10, 30, 100 % x 128 and 16 KiB) x 2 modes x 3 runs x 2 trees = 96 runs, R first then D, modes
alternated within each case (run 1 and 3: hybrid then redirect; run 2: redirect then hybrid). Each run:
  0. fixture create DIR <rec> <pct> 100 in a fresh DIR (runs/<tree>-r<rec>-p<pct>-<mode>-<n>);
  1. fixture_adapter DIR move <mode>: import, inventory, census walk alone, scrub, parity-2 epoch, pre-flight,
     mover, census (must be 0), export;
  2. fixture verify DIR (cold, read-only); its VERIFY sha256 lines also compared with run.py's own expected_sha()
     (imported unchanged);
  3. fixture_adapter DIR report (read-only import): table entries, bytes, kept sectors, heap after a cold import;
  4. fixture drop-retained DIR; 5. report again; 6. fixture verify DIR again;
  7. D only: fill (hybrid_probe's ENOSPC and gang check) on a sparse copy of DIR taken after step 6.
Mover wall time = from the move's census to its final census and txg sync (hybrid_probe's "migration, census
included"); I/O and txgs = root vdev_stat and last synced txg deltas over the same window.
Heap = mallinfo2().uordblks sampled every 10 ms (>= 147 samples per move); glibc serves the census's own arrays
(scratch_bytes = 40894464, 39 MiB) by mmap, so they appear in hblkhd, not uordblks: the "peak+mmap" column adds
hblkhd. Both include libzpool's caches (ARC, dbufs).

== development finding before the runs (logs and core kept in dev-findings/1-physical-rewrite)

  VERIFY3U(feature_get_refcount(spa, feature, &refcount), !=, ENOTSUP) failed (95 != 95), zfeature.c:413,
  feature_do_action(SPA_FEATURE_PHYSICAL_REWRITE, INCR) <- dsl_dataset_activate_feature <- dsl_dataset_sync_done.
dmu_buf_will_rewrite() (the hybrid's rewrite, as zfs rewrite -P) activates feature@physical_rewrite; the generator
enables only raidz_parity_epochs (hybrid_probe's own pools enable every feature). The adapter now enables
physical_rewrite (and extensible_dataset, its dependency) in a sync task before the move in hybrid mode, as zpool set
feature@physical_rewrite=enabled would, and records it (physical_rewrite_enabled_by_adapter=1 in all 48 hybrid runs;
it was enabled in none of the inputs). A change the spike could take instead (not made): have the hybrid's rewrite
path check the feature and refuse or enable it, as the kernel's zfs rewrite -P checks it.
